NOVA DOWNLOADER — نسخة Vercel + خادم تنزيل خارجي
================================================

مهم: هذه النسخة تفصل واجهة الموقع عن محرك التنزيل.
- الواجهة الأمامية تُرفع على Vercel.
- محرك yt-dlp وFFmpeg يعمل على خادم خارجي يدعم Python وDocker.
- لا تضع محرك التنزيل داخل Vercel Functions؛ التنزيلات الطويلة والملفات الكبيرة ليست مناسبة لها.

الملفات
-------
index.html / style.css / app.js : واجهة الموقع.
config.js : مكان وضع رابط خادم التنزيل.
server.py : واجهة API لمحرك التنزيل.
Dockerfile : تجهيز الخادم مع FFmpeg.
requirements.txt : مكتبات Python.
vercel.json : إعداد نشر الواجهة على Vercel.

أولاً: نشر الواجهة على Vercel
-----------------------------
1) ارفع محتويات مجلد NOVA-Downloader إلى GitHub.
2) في Vercel اختر Add New > Project ثم اربط المستودع.
3) اجعل Root Directory هو مجلد NOVA-Downloader إذا كان داخل مجلد أكبر.
4) لا تحتاج Build Command؛ اترك إعدادات الموقع الثابت الافتراضية.
5) انشر الموقع. سيظهر رابط مثل https://your-project.vercel.app.

ثانياً: نشر محرك التنزيل على خادم خارجي
--------------------------------------
الخيار الموصى به: خادم Ubuntu/VPS يدعم Docker وقرص تخزين دائم.
1) ارفع مجلد NOVA-Downloader إلى الخادم.
2) ثبّت Docker وDocker Compose.
3) أنشئ مجلداً دائماً للملفات، مثال: /opt/nova-data.
4) شغّل الحاوية بالأوامر التالية من مجلد المشروع:

   docker build -t nova-downloader .
   docker run -d --name nova-downloader --restart unless-stopped \
     -p 8765:8765 -e ALLOWED_ORIGINS=https://your-project.vercel.app \
     -v /opt/nova-data:/data nova-downloader

5) اربط نطاقاً فرعياً بالخادم وفعّل HTTPS عبر Nginx/Caddy أو لوحة مزود الخادم.
6) اختبر: افتح https://YOUR-BACKEND-DOMAIN/api/health
   يجب أن تظهر نتيجة JSON فيها ok:true.

ثالثاً: ربط Vercel بالخادم
-------------------------
1) افتح config.js.
2) استبدل YOUR-BACKEND-DOMAIN بالرابط الحقيقي لخادمك، مثال:
   API_BASE_URL: "https://api.example.com"
3) ارفع التعديل إلى GitHub؛ سيعيد Vercel النشر تلقائياً.
4) افتح الموقع واضغط تحديث حالة المحرك. يجب أن تظهر «المحرك متصل».

تنبيهات مهمة
------------
- لا يمكن أن يعمل التنزيل عبر Vercel وحده؛ لا بد من تشغيل الخادم الخارجي وربطه.
- استخدم خادماً بقرص دائم ومساحة كافية؛ ملفات الفيديو تستهلك مساحة كبيرة. احذف الملفات القديمة دورياً.
- هذه النسخة تحتفظ بحالة المهام في ذاكرة الخادم؛ إعادة تشغيل الخادم تصفّر سجل المهام، وقد تحذف الملفات إذا لم تستخدم قرصاً دائماً.
- لم نضف نظام مستخدمين أو حصص تنزيل أو حماية API بمفتاح. لا تترك الخدمة عامة دون حماية إذا كان الخادم محدود الموارد؛ أضف مصادقة/حدود استخدام قبل فتحها للجمهور.
- بعض المواقع لا تسمح بالتنزيل أو قد لا تكون مدعومة. لا تتجاوز DRM أو تسجيل الدخول أو الاشتراكات أو قيود الوصول. نزّل فقط المحتوى الذي تملك حق تنزيله أو يسمح الموقع بذلك.
- لا يمكن ضمان تنزيل كل روابط YouTube أو Qesen؛ دعم yt-dlp يتغير حسب الموقع وسياساته.

استكشاف الأخطاء
----------------
المحرك غير متصل: تأكد من أن API_BASE_URL صحيح، وأن /api/health يفتح عبر HTTPS، وأن ALLOWED_ORIGINS يحتوي رابط Vercel الصحيح.
فشل التحليل: قد يكون الموقع غير مدعوم أو الرابط خاصاً/منتهياً أو يتطلب صلاحيات لا يجوز تجاوزها.
فشل FFmpeg: تأكد من تشغيل Dockerfile المرفق، فهو يثبت FFmpeg داخل الحاوية.
